# Design Document: OpenClaude Session Tracking in Joplin

**Version:** 1.0  
**Date:** 2026-04-25  
**Status:** Design / Pre-implementation  
**Scope:** Passive capture of every OpenClaude session into Joplin as a searchable, structured memory record

---

## 1. Problem Statement

Every OpenClaude session produces valuable knowledge — decisions made, code written, bugs fixed, patterns discovered. Today that knowledge evaporates when the session ends. The only trace is:

- A brief `## YYYY-MM-DD — session ended HH:MM` marker written to a monthly "Memories" Joplin note (when `save-memory.sh` runs — which it currently doesn't, because it is **not wired into `settings.json`**)
- Whatever the user manually runs `/remember` for mid-session

This means questions like *"what was I working on last Tuesday?"* or *"when did I decide to use TanStack Query?"* require digging through terminal history or trying to remember.

**Goal:** Every OpenClaude session — regardless of project, length, or outcome — automatically produces a structured, searchable Joplin note that captures what was done, why, and what was decided.

---

## 2. What "a session" means

An OpenClaude session is bounded by:
- **Start:** the first message the user sends
- **End:** the user exits (`/exit`, `Ctrl+C`, window close) → triggers the `Stop` hook in `settings.json`

One session = one Joplin note.

The session happens in the context of a **working directory** (the repo OpenClaude was launched from). This is the primary grouping dimension.

---

## 3. What to capture per session (scope)

These are ordered by value-to-effort ratio.

### 3.1 Must have (MVP)
| Field | Source | Notes |
|-------|--------|-------|
| Date + time (start, end) | Shell `date` in hook | Always available |
| Working directory / repo name | `$PWD` in hook | Identifies which project |
| Session duration | Calculated from start/end timestamps | Stored in session state |
| **Task summary** (1–3 sentences) | Generated by a lightweight LLM call at session end | "What did this session accomplish?" |
| **Files changed** | `git diff --name-only HEAD` at session end | Which files were modified |
| **Commits made** | `git log --oneline --since="session_start"` | Concrete artifacts |
| **OpenClaude TodoWrite tasks** | Read `.claude/todos.json` if it exists | What was planned vs done |

### 3.2 Should have (V2)
| Field | Source | Notes |
|-------|--------|-------|
| Decisions made | Parse `/remember decision:` calls from session | Already structured |
| Tools used | Count of Bash/Read/Write/Edit invocations | Characterises the session type |
| Error patterns | Grep for "failed", "error" in session output | Useful retrospective signal |
| Related Joplin notes | Cross-reference repo name against notebook titles | Contextual links |

### 3.3 Out of scope (for now)
- Full conversation transcript (too large, privacy concern)
- Screenshot thumbnails from 2brn captures during session
- Diff of actual code changes (too verbose — commit SHAs are enough)

## 4. Where sessions are stored in Joplin

### Notebook structure
```
Joplin
└── OpenClaude Sessions          ← new notebook, created once
    └── 2026-04                  ← monthly sub-notebook (or flat, see below)
        ├── 2026-04-25 2brn — code review fixes
        ├── 2026-04-25 2brn — TanStack Query migration
        └── 2026-04-23 SDA — microservices migration
```

**Decision: flat within a monthly notebook** (not by project). Rationale: queries like "what did I do last week?" are time-based, not project-based. Use tags for project filtering instead.

### Note title format
```
YYYY-MM-DD HH:MM — <repo-name> — <short-task-description>
```
Example: `2026-04-25 14:32 — 2brn — TanStack Query navigation performance fix`

The short task description is the first line of the LLM-generated summary, truncated to ~50 chars.

### Note body format
```markdown
# 2026-04-25 14:32 — 2brn

**Duration:** 47 minutes  
**Repo:** `/Users/sasidharan/…/2brn`  
**Branch:** `feat/implementation`  

## Summary
Migrated the 2brn React UI from manual `useState+useEffect` data fetching
to TanStack Query v5. Eliminated ~2500ms navigation delays caused by
StrictMode double-mounting and zero caching.

- `ui/src/App.tsx` — lifted DaemonStatus+StatsBar into persistent layout
- `ui/src/components/Timeline.tsx` — migrated to useQuery
- `ui/src/components/Insights.tsx` — migrated to useQuery
- *(+8 more files)*

## Commits
```

## 5. Architecture

### 5.1 How the hook fires

The `Stop` hook in `~/.openclaude/settings.json` fires when any session ends:
```json
"hooks": {
  "Stop": [
    {
      "hooks": [
        {
          "type": "command",
          "command": "/bin/bash ~/.openclaude/hooks/session-to-joplin.sh",
          "async": true
        }
      ]
    }
  ]
}
```

**Note:** The current `save-memory.sh` is disconnected — this is a pre-existing bug. The new system replaces and supersedes `save-memory.sh`. The monthly "Memories" marker can be written by the new hook too, preserving backward compatibility.

### 5.2 The session state problem

The Stop hook fires at session end. To write a rich summary, we need data from the entire session:
- When did the session start?
- What was the initial task/goal?
- What git changes happened?

**Solution: session start hook + session state file**

Add a `PreToolUse` or a one-time write at session start that records:
```json
// ~/.openclaude/session-state.json (overwritten each new session)
{
  "session_id": "uuid-v4",
  "started_at": "2026-04-25T14:32:00+05:30",
  "working_dir": "/Users/sasidharan/…/2brn",
  "repo_name": "2brn",
  "git_sha_start": "670dfb6",
  "git_branch": "feat/implementation"
}
```

This is written by a `PreToolUse` hook on the very first tool call, or by a startup script. The Stop hook reads it to compute duration and git delta.

### 5.3 LLM-generated summary

The summary field requires intelligence. Options:

**Option A: Call your AI provider directly from the hook (recommended)**
- The hook script calls `http://<your-provider-host>/v1/chat/completions` with a structured prompt:
  ```
  Summarise this OpenClaude coding session in 2-3 sentences.
  Repo: 2brn | Duration: 47 min | Changed files: [list] | Commits: [list]
  ```
- Requires the gateway to be running (it always is during a session)
- Falls back gracefully if gateway is unreachable — writes "Summary unavailable" and still records the factual data

**Option B: Use the 2brn daemon's `/chat` endpoint**
- Only works if the 2brn app is running (not always true)
- Creates a circular dependency concern

**Option C: No LLM, just structured facts**
- Simpler, more reliable, but loses the human-readable narrative
- Could be added later as an enhancement

**Recommendation: Option A with Option C fallback.**

### 5.4 Component diagram

```
OpenClaude session starts
        │
        ▼
[PreToolUse hook] → writes ~/.openclaude/session-state.json
  (first tool use only, via state file check)
        │
        │  ... session continues ...
        │
        ▼
OpenClaude session ends (Stop hook fires)
        │
        ▼
[session-to-joplin.sh]
    ├── reads session-state.json (start time, repo, branch, starting SHA)
    ├── runs: git diff --name-only <start_sha>..HEAD
    ├── runs: git log --oneline <start_sha>..HEAD
    ├── reads: .claude/todos.json (if exists)
    ├── reads: ~/.openclaude/session-decisions.jsonl (decisions logged mid-session)
    ├── calls: your AI provider /v1/chat/completions → summary text
    ├── formats: Markdown note body
    └── calls: Joplin Web Clipper POST /notes → creates note in "OpenClaude Sessions" notebook
        │
        ▼
    [also] appends monthly "Memories" marker (backward compat)
        │
        ▼
    [also] clears session-state.json (ready for next session)
```

## 6. The `/remember` skill integration

The current `/remember` skill writes individual bullets to specific Joplin notes. This is preserved. The new design adds a second write path:

When the user calls `/remember decision: X`, in addition to appending to "Decisions — YYYY-MM", we also append to a `~/.openclaude/session-decisions.jsonl` file:
```json
{"ts": "2026-04-25T14:45:00", "type": "decision", "text": "Removed StrictMode…"}
```

The Stop hook then collects all session decisions from this file into the note's "Key decisions" section, then clears the file.

This gives us:
1. **Live access** — decisions in Joplin immediately (existing behaviour)
2. **Session context** — decisions grouped into the session note at end

## 7. 2brn integration: session notes as searchable memories

This is where Level 1 becomes part of Level 4.

The `JoplinWatcher` already polls Joplin every 60 seconds and embeds changed notes into ChromaDB `note_memories`. Session notes written to Joplin will automatically be picked up, chunked, embedded, and made searchable via 2brn's chat interface.

This means:
- "What was I building last Tuesday?" → 2brn RAG search → finds the session note from Tuesday → answers with specific commits, files, decisions
- "When did we decide to use TanStack Query?" → finds the session note where that decision was made → returns exact date + rationale
- "What's the status of the SDA microservices work?" → finds all SDA session notes → synthesises current state

**No additional code needed** in 2brn to make this work — it flows automatically through the existing `JoplinWatcher` pipeline.

## 8. What requires Joplin to be open

| Operation | Requires Joplin | Notes |
|-----------|----------------|-------|
| Write session note at end | **Yes** (Web Clipper) | Fall back: save to `.claude/pending-sessions/` and upload when Joplin next opens |
| Read session notes in chat | No (SQLite read) | Works any time |
| Search sessions in 2brn | No | ChromaDB |

**Offline fallback:** If Joplin is closed when the Stop hook fires, write the formatted note to `~/.openclaude/pending-sessions/YYYY-MM-DD-HH-MM-session.md`. A `PostToolUse` hook on the next session checks this directory and uploads any pending notes on session start.

---

## 9. Daily journal relationship

The 2brn daemon already writes daily journals to Joplin at 14:00 (morning) and 20:30 (evening). These journals summarise **screen activity** (OCR → inference summaries).

Session notes are complementary — they capture **intent and decisions** rather than passive screen activity. Together they give a complete picture:

- **Daily journal (2brn):** "You spent the afternoon in VS Code and Slack"
- **Session note (OpenClaude):** "You fixed the inference queue OOM bug and migrated the UI to TanStack Query"

They live in different Joplin notebooks but both feed into ChromaDB via `JoplinWatcher`, so 2brn chat searches both simultaneously.

## 10. Open questions / decisions needed

| Question | Options | Recommendation |
|----------|---------|----------------|
| How rich should the summary be? | Facts only / LLM summary / Full narrative | LLM summary (2–3 sentences) with facts below |
| One note per session or daily aggregate? | Per session / Daily | Per session — more granular and searchable |
| Where is session state stored? | `~/.openclaude/session-state.json` / SQLite | Simple JSON file — no dependencies |
| What if gateway is unreachable? | Fail silently / Write without summary | Write note with "summary unavailable" — facts are more important |
| Should session notes be tagged? | Yes / No | Yes — repo name as tag enables per-project filtering |
| Global hook (all projects) or per-repo? | Global `~/.openclaude/settings.json` / `.mcp.json` | Global — sessions happen across many repos |

## 11. Implementation phases

### Phase 1 (MVP — ~4 hours)
1. Fix `settings.json` Stop hook — wire in `session-to-joplin.sh`
2. Write `session-to-joplin.sh` — captures git facts, calls gateway for summary, posts to Joplin
3. Add `PreToolUse` hook to write `session-state.json` at session start
4. Test: run a session, verify note appears in Joplin

### Phase 2 (~2 hours)
5. Add decision accumulation to `~/.openclaude/session-decisions.jsonl`
6. Modify `/remember` skill to also write to the accumulator file
7. Offline fallback: pending sessions directory + upload on next session start

### Phase 3 (~1 hour)
8. Verify JoplinWatcher picks up session notes and embeds them
9. Test end-to-end: ask 2brn "what was I working on yesterday?" — confirm session notes appear in answer
