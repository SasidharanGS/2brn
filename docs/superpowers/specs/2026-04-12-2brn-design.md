# 2brn — Second Brain App · Design Specification

**Date:** 2026-04-12  
**Status:** Approved  

---

## Context

2brn is a personal "second brain" desktop app that runs silently in the background, periodically capturing screenshots of the user's screen, inferring what they are doing, and storing that knowledge locally. The user can later chat with the app to recall past activity, browse an auto-generated daily journal, and gain productivity insights — all without any data leaving the machine (raw data stays local; only extracted text summaries are sent to the LLM gateway).

The core problem: people forget what they worked on, lose context between sessions, and have no objective record of how they actually spend their time. 2brn solves this passively — no manual input required.

---

## Goals

- Capture what the user does on their computer with zero manual effort
- Infer activity type, task category, and productivity state automatically
- Allow the user to recall any past activity through natural language chat
- Generate a readable daily journal narrative automatically
- Surface productivity insights (time spent per category, productive vs. procrastinating)
- Run with minimal system resource usage — always on, never in the way
- Keep all raw data 100% local; use JLL GPT Gateway for LLM inference only

---

## Non-Goals (v1)

- Mobile app or web access
- Multi-device sync
- Real-time notifications or nudges
- Manual tagging or note-taking UI
- Audio/microphone capture

### Platform

- **Cross-platform from day one**: macOS, Windows, Linux
- **App shell**: Electron (distribution + native OS integration)
- **UI**: React + TypeScript
- **Daemon**: Python 3.12 (runs as a background process, independent of the UI)
- **IPC**: FastAPI HTTP server on localhost — UI calls daemon endpoints
- **LLM**: JLL GPT Gateway at `localhost:8888` — OpenAI-compatible `/v1/chat/completions` with Bearer token auth

## Components

### 1. Capture Engine

Runs inside the Python daemon. Two triggers:

- **Heartbeat**: Every 60 seconds unconditionally (journal continuity)
- **Change detection**: Pixel diff via `mss` — fires immediately when screen changes significantly (app switch, new window, major content change)

On each capture:
1. Grab full screenshot via `mss` (cross-platform)
2. Read active app name + window title via accessibility API (`pygetwindow` on Windows/Linux, `AppKit` on macOS)
3. Compute perceptual hash via `imagehash` — if >95% similar to previous stored frame, discard immediately (no OCR, no storage, no LLM call)
4. If unique: compress to JPEG 80% quality (~40–80KB), save to disk, run Tesseract OCR, write to SQLite `captures` table
5. Push OCR text to async inference queue (non-blocking)

Excluded apps (from `app_exclusions` table) are skipped entirely — no screenshot taken.

### 2. OCR Pipeline

- Library: `pytesseract` wrapping Tesseract
- Runs synchronously after dedup check, before inference queue
- Output: raw text string stored in `captures.ocr_text`
- Fallback: if OCR yields < 20 chars (image-heavy screen), flag for optional vision inference in future versions

### 3. Inference Worker

- Async Python queue consumer — runs independently of capture
- Batches frames every 30 seconds
- Sends to JLL GPT Gateway a single structured prompt per frame:

```
Given this screen content, return a JSON object with:
- summary: 1-2 sentence description of what the user was doing
- tags: array of specific activity keywords
- task_category: one of [work, research, play, learning, communication, creative, admin, other]
- task_category_confidence: float 0–1
- productivity_state: one of [productive, focused, chilling, procrastinating, distracted, in-meeting, idle]
- productivity_confidence: float 0–1

Screen content:
App: {app_name} | Window: {window_title}
OCR text: {ocr_text}
```

- Response written to SQLite `activities` table
- Summary + metadata written to ChromaDB `activity_memories` collection

### 4. Embedding Service

- Uses JLL GPT Gateway embeddings endpoint (OpenAI-compatible)
- Embeds each activity summary after inference completes
- Stores embedding in ChromaDB with metadata: `timestamp`, `app_name`, `tags`, `date`, `task_category`, `productivity_state`
- `chroma_id` written back to `activities` table to link SQLite ↔ ChromaDB

### 5. Journal Generator

- Scheduled: runs at midnight (or manually triggered from UI)
- Fetches all `activities` rows for the day from SQLite
- Sends consolidated summaries to JLL GPT Gateway:

```
Write a natural, first-person journal entry for this day.
Tone: reflective, honest, human. Include: what was worked on, 
key moments, productivity observations. Do not be preachy.
Activities: {daily_summaries}
```

- Saves output as markdown to `journals` table
- Never overwrites entries where `edited_by_user = true`

### 6. Chat API (RAG)

FastAPI endpoint: `POST /chat`

Pipeline:
1. Embed user query via JLL GPT Gateway embeddings
2. Semantic search in ChromaDB `activity_memories` (top 10 results), filtered by optional date/category/productivity metadata
3. Fetch surrounding context from SQLite for each result
4. Build prompt: system context + retrieved chunks + user question
5. Stream response from JLL GPT Gateway back to UI via Server-Sent Events

### 7. Electron UI

**Dashboard (home screen)**
- Live stats bar: current productivity state · time in current task category today · overall productive % today
- Central chat input (always visible)
- Quick nav tiles: Journal · Timeline · Insights · Settings
- Daemon status indicator (capturing / paused / error)

**Chat view**
- Full conversation thread with streaming responses
- Source citations — each answer links back to the captures it was derived from
- Date filter chips for scoping queries

**Journal view**
- Calendar picker to browse past days
- Rendered markdown journal entry
- Edit button (sets `edited_by_user = true`, preserves user edits)
- Regenerate button (only if `edited_by_user = false`)

**Timeline view**
- Horizontal timeline of the day's captures, grouped by app/activity
- Colour-coded by `task_category`
- Click a block to see the screenshot thumbnail + summary
- Scrubber to navigate across the day

**Insights view**
- Time breakdown by `task_category` (bar chart — daily/weekly/monthly)
- Productivity state distribution (pie/donut chart)
- Top apps by time spent
- Trend lines: productive hours per day over last 30 days
- Low-confidence classification flags — click to correct and set `category_overridden_by_user = true`

**Settings view**
- JLL Gateway URL + Bearer token configuration
- Capture frequency override
- Excluded apps management (add/remove from `app_exclusions`)
- Storage management: current disk usage, manual purge, auto-purge period (default 6 months)
- Pause/resume capture toggle

## Data Flow Summary

1. **Capture** → `mss` grabs screenshot + reads active app/window
2. **Dedup** → perceptual hash check; discard if >95% similar to previous
3. **Store** → JPEG to disk, OCR via Tesseract, write to `captures` table
4. **Infer** (async queue) → OCR text → JLL GPT Gateway → structured JSON → write to `activities` table
5. **Embed** → summary → JLL GPT Gateway embeddings → ChromaDB
6. **Journal** (end of day) → daily summaries → JLL GPT Gateway → markdown prose → `journals` table
7. **Chat** (on demand) → query embed → ChromaDB semantic search → SQLite context → JLL GPT Gateway → streamed answer

## Error Handling

- **Gateway unavailable**: Inference worker retries with exponential backoff (max 3 attempts). Raw OCR text is preserved in SQLite — inference can be run retroactively when the gateway comes back online.
- **OCR failure**: Log and continue. Capture is stored with empty `ocr_text`; inference skipped for that frame.
- **ChromaDB write failure**: Log with capture ID. SQLite record written regardless. Re-sync can be triggered from Settings.
- **Electron ↔ daemon disconnected**: UI shows "daemon offline" indicator. Daemon is auto-restarted by Electron on reconnect failure after 10s.
- **Disk full**: Capture paused, user notified via UI banner. Auto-purge runs immediately on oldest frames.

---

## Privacy & Security

- Raw screenshots **never** leave the machine
- Only extracted text summaries (no images) sent to JLL GPT Gateway
- `app_exclusions` table allows blocking sensitive apps (banking, password managers) — no screenshot taken at all when those apps are active
- SQLite database and ChromaDB stored in `~/.2brn/` — user-owned, user-deletable
- Bearer token for JLL Gateway stored in OS keychain (not in config.json plaintext)
- All daemon ↔ UI communication on localhost only

## Verification Plan

### Daemon
- Unit test: dedup hash check correctly discards near-identical frames
- Unit test: inference prompt produces valid structured JSON across edge cases (empty OCR, non-English text, image-only screens)
- Integration test: end-to-end capture → OCR → inference → SQLite write → ChromaDB embed pipeline
- Load test: daemon CPU/RAM stays under 5% average during normal operation

### UI
- Chat RAG returns coherent answers for date-scoped and category-filtered queries
- Journal generates readable markdown prose from a full day of activities
- Timeline renders correctly for days with 100+ captures
- Insights charts aggregate `task_category` and `productivity_state` correctly

### End-to-end
- Open VS Code for 5 minutes → open browser for 5 minutes → query chat: "what did I do in the last 10 minutes?" → verify accurate response
- Trigger end-of-day journal generation → verify readable narrative in Journal view
- Add an app to `app_exclusions` → verify no captures taken while that app is active
- Fill disk to trigger auto-purge → verify oldest files removed, capture resumes
